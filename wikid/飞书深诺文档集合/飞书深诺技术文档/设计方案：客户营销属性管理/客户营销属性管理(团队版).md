### 全局约定（适用于所有 BFF 接口）
**1. webhookId 不由前端传**：所有 BFF 接口**前端不用传 ****webhookId**（属性 CRUD `/marketing/attribute/*` + 通用导入 `/import/*`）。BFF 内部从用户会话 `RequestHolder.getStoreId()` 取，转调 core Feign 时自动注入。  
**2. 分页字段（双层约定）**：BFF 列表接口（前端→jservice 入参）统一用 `pageNum` + `pageSize`，与 jservice-api 现有 BFF 请求 DTO 约定一致（如 `PageRequest`/`PageDTO`/`CatalogProductListReq`；复用的 `/export/list` 即 `ExportListRequest extends PageDTO`，也是 `pageNum`）；core 内部 Feign（`QueryTaskListReq`/`QueryTaskDetailReq`/`BasePageDto`）沿用 `pageNo`，由 BFF 适配层做 `pageNum → pageNo` 转换。  
> **出参约定**：列表类接口出参统一沿用现有 jservice BFF 惯例 `PageResult<T>{ total, result }`——**只回显 ****total**** 与 ****result****，不回显页码**（前端自管理 `pageNum`/`pageSize`），与 `BatchExportLogServiceImpl.listPage` 等现有实现一致。营销属性 `list` / `value/page` 出参均为 `PageResult<ListItem>` / `PageResult<PageItem>`。`lastId` 仅用在导出场景的 core 内部数据拉取。  
**3. 任务列表支持状态/操作人过滤**：`/import/task/list` 支持可选的 `taskType`、`taskStatus`（`PREPARE`/`INIT`/`SUCCESS`/`FAIL` 列表过滤）和 `operatorId`（按操作人过滤）。

### 核心数据流
```
① 营销属性管理：前端 → jservice /marketing/attribute/list/create/updateName/delete → Feign → core IMarketingAttributeController → marketing_attr
② 批量导入（**通用导入通道 /import/*，按 taskType 分发**，参照 catalog 批量上传模式）：
   - 模板下载：前端 → jservice `POST /import/template`（taskType=9 + attributeIds）→ BFF ImportTemplateHandlerFactory 按 taskType 取 MarketingAttributeImportTemplateHandler → 拼表头 → 上传云存储 → 返回 url
   - 创建任务：前端 → jservice `POST /import`（taskType + storyKey + fileName + attributeIds）→ BFF ImportTaskAssemblerFactory 按 taskType 取 MarketingAttributeImportTaskAssembler → 校验属性属本店 → 组装 FileTaskContentDto → core **通用** `insertPrepareTask(TaskType=9, ...)` → rp_task(PREPARE)
   - prepare：jservice 已有定时器 /scheduled/task/execute 扫描 downLoadTask=true 的 PREPARE → 新 ImportMarketingAttributeExecution.prepare 下载/校验/去重/落 rp_task_detail(INIT)
   - 执行：jservice `/scheduled/task/execute` 末尾回调 core `ITaskController.executeMarketingAttributeImportTasks()` → 分布式锁 → 扫描 type=9 INIT 任务 → ImportMarketingAttributeTaskExecutor.executeBatch 增量去重 → 落 marketing_attr_value（值去重字典）+ marketing_attr_rel（关系表）+ marketing_attr_search（ES 同步表）→ binlog+DTS 同步 → ES（供模糊检索）
   - 任务列表/失败明细：前端 → jservice `POST /import/task/list`（taskType 过滤）→ 复用 core queryTaskList/queryDetailsByTaskIdAndStatus（按 TaskType=9 过滤）
③ 导出：前端 → jservice /export/create/task(type=18) → 现有 BatchExportLogServiceImpl.save → Kafka exportDataTaskTopic → 现有 handlerExportTask 新增 case → MarketingAttributeValueExportService.export → core Feign /marketing/attribute/value/export/page lastId 分页拉数据 → EasyExcel → 云存储 → rp_batch_export_log
④ 发送替换：dialogue sendMessage 批量预取 ThreadLocal → fillSystemParam 提取残留 {{var}} → 剔除系统/扩展字段名 → 剩余视为营销属性 → core Feign /marketing/attribute/value/batch（命中替换/未命中置空；占位符由前端直接插入内容，不做 /params/groupList 分组展示）
```

**结论**：本期导入采用 **通用导入通道 + catalog 核心模式**：BFF 层收敛到 `/import/*`（按 `taskType` 分发，由 `ImportTemplateHandler` / `ImportTaskAssembler` 工厂按类型扩展），core 层**通用**`insertPrepareTask`（与 customer/import/new 同模式，不新增专用 Feign）+ core 执行（`currentServiceRun=true`）。理由：① 06-change-rules 硬约束（jservice 禁新增直连存储）；② 数据归属 core，落库在数据所在地；③ 通用导入通道可复用于后续批量导入场景（只需新增 `taskType` + 对应 bean）。

// 入口：core MarketingAttributeCommandService.create(req)
function create(req) {

// ========== jservice prepare（ImportMarketingAttributeExecution） ==========
function prepare(taskDTO) {
    content = parseFileTaskContent(taskDTO);             // 拿 storyKey/fileName/attributeIds
    rows = downloadAndParse(content.storyKey, content.fileName);
    checkTitle(rows.title, content.attributeIds);          // 列0=手机号、列1=用户id必在；其余按 attributeIds 顺序匹配属性名
    lines = dealWithLineAndValidate(rows.data, content.attributeIds); // 逐行解析；手机号与用户id均空/属性值空 → 跳过（无效数据）
    lines = dedupeInFile(lines, content.attributeIds);     // 按 external_user_id 去重（缺失则用 mobile）；券码按 (attrIdx, couponCode) 去重；自定义不查重
    partition(lines, 200).forEach(insertTaskDetails);     // 分批落 rp_task_detail(INIT)
}

// ========== core 触发入口（由 jservice /scheduled/task/execute 回调）==========
// 本期不在 core 新增 timer 端点；jservice execution() 末尾调 taskController.executeMarketingAttributeImportTasks()
// → core 分布式锁扫描 type=9 INIT：
function scanAndExecuteMarketingAttributeTasks() {
    distributedLockService.tryLockSyncExecute(() -> {
        for (TaskType type : TaskType.values()) {
            if (!type.currentServiceRun) continue;   // 仅扫描 core 执行的 taskType（含 type=9）
            scanAndExecute(type);
        }
    }, LOCK_KEY);
}

// ========== core 执行器（ImportMarketingAttributeTaskExecutor extends AbstractCatalogProductHandleTaskExecutor） ==========
function executeBatch(task, details) {
    for (detail : details) {
        row = parseRow(detail);
        if (isBlank(row.mobile) && isBlank(row.externalUserId)) { fail(detail); continue; }                  // 手机号/用户id 至少其一
        if (isBlank(row.value)) { fail(detail); continue; }                                                   // 属性值非空
        key = isBlank(row.externalUserId) ? row.mobile : row.externalUserId;                                  // 客户唯一键：优先用户id
        if (exists(row.attributeId, key)) { fail(detail); continue; }                                          // 同一客户重复（未删除）
        if (isCoupon(row) && exists(row.attributeId, row.value)) { fail(detail); continue; }     // 券码重复
        valueId = upsertDict(attributeId, row.value);  // 写 marketing_attr_value（attribute_id+value 唯一，存在则复用）
        insert marketing_attr_rel(attributeId, valueId, row.mobile, row.externalUserId);  // 关系表（mobile + external_user_id）
        insert marketing_attr_search(webhookId, attributeId, row.mobile, row.externalUserId, value, valueId, importTime);  // ES 同步表（反范式，冗余 value_id 便于回删、import_time 供筛选）
        // binlog + DTS 自动同步到 ES（无需手动写）
        success(detail);
    }
    updateTaskStatus(task, successCount, failCount);
    // 刷新受影响属性的统计列（客户数 / 最近导入时间），避免每次列表聚合
    for (attrId in distinctAttributeIds(details)) {
        update marketing_attr set
            customer_count = (select count(distinct external_user_id) from marketing_attr_rel where attribute_id=attrId and is_deleted=0),
            last_import_time = (select max(import_time) from marketing_attr_rel where attribute_id=attrId and is_deleted=0)
        where id = attrId;
    }
}

#### 功能点 5：内容发送变量替换
**工作流**：
`fillSystemParam` 现有系统参数/业务字段替换完成后，正则提取残留 `{{xxx}}` → 剔除系统变量/业务字段名 → 剩余视为营销属性变量名 → core Feign 批量查询 `(webhookId, mobile【即接收人 channel_user_id 归一手机号】, variableNames)` → 属性存在则替换值（可能为空字符串）；属性已删除或不存在则替换为空字符串（**与系统变量空值处理逻辑一致：始终替换，不报错、不静默终止、不保留原文**）。批量 toList 场景在 sendMessage 外层批量预取入 ThreadLocal。OpenAPI 发送场景同样适用（MB 系统发送时变量为空的效果一致）。  
**关键步骤细化（伪代码描述）**：  
```
// ========== sendMessage 外层（WhatsAppMessageSendHandlerServiceImpl.sendMessage）==========
// 批量预取，避免 N+1 Feign 调用
vars = extractMarketingVarNames(sendDto.contents);   // 提取 {{xxx}}，剔除系统变量/业务扩展字段名
if (CollectionUtils.isNotEmpty(sendDto.toList) && CollectionUtils.isNotEmpty(vars)) {
    MARKETING_ATTR_MAP_TL.set(coreFeign.valueBatch(sendDto.webhookId, sendDto.toList, vars));
}
try {
    for (receiver : sendDto.toList) fillSystemParam(receiver, sendDto.contents);
} finally {
    MARKETING_ATTR_MAP_TL.remove();   // 清理 ThreadLocal，避免内存泄漏
}

// ========== fillSystemParam 内（兼容单条/批量两条调用路径）==========
function fillSystemParam(receiver, messageData) {
    replaceSystemParams(messageData);                  // 现有：系统参数
    replaceBusinessExtendFields(messageData);          // 现有：业务扩展字段
    // 新增：营销属性替换
    vars = extractRemainingVars(messageData);           // 残留 {{xxx}}
    vars.removeAll(systemParamNames);                  // 剔除系统变量
    vars.removeAll(businessExtendFieldNames);          // 剔除业务字段
    map = MARKETING_ATTR_MAP_TL.get()?.get(receiver.channelUserId);
    if (map == null) map = coreFeign.valueBatchOne(webhookId, receiver.channelUserId, vars);   // 单条兜底（TL 空场景）
    for (v : vars) {
        messageData = messageData.replace("{{" + v + "}}", map.getOrDefault(v, ""));  // 始终替换：属性存在替换值（可能为空），不存在替换为空字符串（与系统变量空值处理一致）
    }
}
```
