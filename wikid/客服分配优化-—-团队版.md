## 二、整体方案
- **架构概要**：在 chooseSeatV2 分配无坐席时记录待分配原因到新增表 `cs_conversation_pending`，支持后续 Job 自动重新分配（仅 `no_online_cs`）；关会话时清理对应 pending 记录；支持全量拉取 + WS 增量推送客服在线状态。
- **数据流简述**：chooseSeatV2 → pendingReason → Kafka chat.status.change → dialogue-engine 消费 → PendingController.record() INSERT 幂等写入 → Job 定时扫描 → sessionPick 分配 → assign
- **涉及服务列表**：meetbot-commons, meetbot-core-client, meetbot-core-service, meetbot-dialogue-engine, meetbot-channel-send, meetbot-jservice-api

## 四、上线文档
### 数据库变更
```
CREATE TABLE `cs_conversation_pending` (
  `id`                 bigint(20)   NOT NULL AUTO_INCREMENT,
  `store_id`           bigint(20)   NOT NULL COMMENT '店铺ID',
  `channel`            varchar(32)  NOT NULL COMMENT '渠道: whatsapp / messenger',
  `customer_id`        varchar(64)  NOT NULL COMMENT 'C端用户ID',
  `conversation_info_id` bigint(20) DEFAULT NULL COMMENT 'rp_user_conversation_info.id',
  `session_type`       varchar(16)  DEFAULT NULL COMMENT '会话类型: YT / KP / ZJ / HF / ECS',
  `pending_reason`     varchar(64)  NOT NULL COMMENT 'no_online_cs / exclusive_cs_not_in_group / quota_exceeded / other',
  `pending_snapshot`   text         DEFAULT NULL COMMENT 'IntentionChooseDto JSON',
  `pending_time`       bigint(20)   NOT NULL COMMENT '进入待分配时间戳(ms)',
  `assigned_user_id`   int(11)      DEFAULT NULL COMMENT '已分配客服ID',
  `version`            int(11)      NOT NULL DEFAULT '0' COMMENT '乐观锁',
  `status`             tinyint(4)   NOT NULL DEFAULT '0' COMMENT '0-待分配, 1-已分配, 2-已取消',
  `created_at`         datetime     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`         datetime     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  `is_deleted`         tinyint(4)   NOT NULL DEFAULT '0',
  PRIMARY KEY (`id`),
  KEY `idx_store_status`     (`store_id`, `status`, `pending_time`),
  KEY `idx_store_customer`   (`store_id`, `customer_id`, `channel`),
  KEY `idx_store_reason_status` (`store_id`, `pending_reason`, `status`, `pending_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='会话待分配记录表';
```

### 发布顺序
1. meetbot-commons 发布（PendingReasonEnum、WebSocketMessageTypeEnum 等）
2. meetbot-core-client 发布（IPendingController 及 DTO）
3. 其他服务更新 core-client 依赖版本
4. meetbot-core-service 发布（DDL + PendingController + chooseSeatV2 写入）
5. meetbot-dialogue-engine 发布（透传 pendingReason/pendingSnapshot）
6. meetbot-channel-send 发布（toManualStatus 透传）
7. meetbot-jservice-api 发布（Job + 离线提示接口）
8. 涉及 DB 迁移脚本执行：是（新增 cs_conversation_pending 表）
9. 涉及配置推送：是（Apollo 配置项 + BotProp）
### 回滚方案
- **代码回滚**：按发布顺序逆序 revert，core-client 回滚需同步回滚依赖方版本
- **数据回滚**：`DROP TABLE IF EXISTS cs_conversation_pending;`
- **配置回滚**：Apollo 配置回退上一版本；BotProp 删除对应 key
- **回滚前提条件**：确认 Job 无进行中任务，pending 表无脏数据
### 自测清单
- [ ] chooseSeatV2 返回无坐席时 pending 记录正确写入（正常流程：待分配记录）
- [ ] 同客户重复触发 record 幂等不重复写入（并发状态：幂等）
- [ ] 关会话时 cancelByRecord 清理 pending 记录（正常流程：清理）
- [ ] Job 扫描仅处理 no_online_cs 记录，其他原因跳过（边界异常：原因过滤）
- [ ] Job 分配成功时 assign 标记 status=1（正常流程：重分配）
- [ ] 人工接起后 Job 跳过（边界异常：已有 OPEN 会话）
- [ ] 分布式锁竞争时正确 skip 而非报错（并发状态：锁竞争）
- [ ] 客服切换离线时弹窗提示 OPEN 会话数正确（正常流程：离线提示）
- [ ] WS ONLINE_STATUS_CHANGE 推送后前端底色更新（正常流程：在线状态）
- [ ] 配置关闭时 Job 不处理对应店铺（边界异常：开关控制）
